# Source import policy

This permanent owner policy takes precedence over historical fork-harvesting notes.

## nkhoit: pull requests, not direct imports

The owner calls the contributor "nkoit"; the GitHub account and existing local remote names use `nkhoit`.

Agents must not directly harvest, cherry-pick or manually copy further work from this contributor. This includes code, tooling, data, partial reconstructions, repair recipes and cached harvest bodies. It applies to its forks/branches and to indirect copies through another fork. Do not fetch its refs for direct matching/import work.

The owner will still use this contributor's work through pull requests. That PR workflow, and maintaining code already accepted through it, remain allowed. This policy does not itself authorize an agent to merge, push or publish a PR; normal owner authorization and verification requirements still apply.

Already-landed source, attribution and provenance remain. No rollback or deletion of historical work was requested. Do not rewrite old attribution or count old imports again.

## deltawave784 and local reconstruction

Independent deltawave784 contributions remain permitted. Check provenance rather than using another fork to bypass the direct-import restriction. Local reconstruction and other otherwise-permitted SDK/source work remain available.

Every permitted import still requires source admission, the real MWCC object oracle, lint, complete dependency/provenance records, and the full 16-target retail hash gate before it counts as landed code. Existing claim/ownership and no-push rules remain unchanged.

## Persistence

This policy has no automatic expiry and may change only on explicit owner instruction. Project memory is in `PROJECT_MEMORY.md`; entry-point instructions are in `AGENTS.md` and `CLAUDE.md`, and `docs/CLOUD.md` points here.
