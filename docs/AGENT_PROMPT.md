# Effective F-Zero GX agent prompt

Copy the prompt below into any coding agent. The repository's current contract
and actual tool surface take precedence over this portable prompt. It grants no
permission to launch workers, change models, bypass budgets, push, or merge.

---

Work on the F-Zero GX decompilation in /home/armandofm/projects/fzgx. Optimize for
new, readable natural C whose linked output passes the repository's retail hash
gate—not activity, rounded object percentages, fuzzy score, or assembly parity.

First read AGENTS.md and CLAUDE.md, inspect the working tree, and discover the
actual CLI/tool schemas. Preserve other people's edits and claims. Do not spawn
agents, change provider/fleet settings, reset attempt caps, add dummy work or
padding, force registers, add inline assembly, encode assembly as data, hardcode
addresses, or push/merge without explicit authorization. Follow the live contract
about tests: it currently prohibits adding unit tests. Validate through actual
compiler probes, existing checks and the full build/hash gate.

Choose the mode your actual environment permits:

- Restricted matcher: use only the assigned function and exposed fzgx tools.
  The runner owns claims, compiler settings, budgets and acceptance. Do not invoke
  shell/CLI commands or shared-header/integration actions. Use supplied context
  and read_evidence(section="decision" or "witnesses") when exposed. If an older
  adapter lacks a section, use the existing context/diff and keep the same
  hypothesis/handoff discipline; do not invent another tool.
- Shell-enabled contributor: inspect `python tools/fzgx.py --help` using the
  repository virtualenv. Consult `evidence queue`, `evidence clusters --module
  MODULE`, and `evidence eligibility SYMBOL` before selecting work. Obtain the
  normal claim without bypassing caps. Do not replace a proven seed with a fresh
  reconstruction. Keep its complete compiler version, flags, types and symbols.
- Shared-structure integrator: only with explicit ownership of shared changes,
  validate a proposed prototype/layout against all affected callers and matched
  siblings. Use the existing headers/TU tools and serialize integration. A
  matching-function agent must instead hand off a shared blocker.

For each function:

1. Read its best saved source, actual compiler profile, retail asm, earlier
   negative experiments and current diff. Use `evidence packet SYMBOL --check`
   only in shell mode when a fresh real replay is needed. A cached packet may
   deliberately have no current residual; do not invent one.
2. Locate the earliest meaningful divergence. Separate accepted layout/pool rows
   from your own differences. Classify it as semantic/control-flow, ABI/type,
   layout/relocation, compiler idiom, register allocation, frame, or mixed.
3. State one falsifiable hypothesis and the instruction change it predicts.
   Check whether unchanged evidence already tested it. For compiler-selection
   questions, retrieve matched native-C witnesses with the same module/compiler
   and preserved register/dataflow pattern before speculative permutations.
4. Change one explanatory factor, compile with the exact saved profile, inspect
   what actually changed, and keep the best valid body. Discard explanations the
   compiler disproves. Never claim a tool was run or a function matched without
   the actual result.
5. Use deterministic search for a supported residual family on eligible input,
   not merely because the score exceeds a threshold. Respect cached zero-yield
   results, tool-reported searches_left and stop budgets. Reopening work requires
   a new source/type/compiler/idiom/donor hypothesis, not another model session.
6. If a shared object, callee ABI or TU declaration is the likely blocker,
   identify the affected cohort and precise evidence needed. Do not casually
   rewrite shared files from an individual function claim.
7. Record a concise handoff through existing release(reason), using actual tool
   observations on separate lines:

   HYPOTHESIS: the source explanation tested
   PREDICTION: the instruction/dataflow change it should cause
   OBSERVATION: what the real compiler/diff returned, including remaining rows
   UNLOCK: the specific new evidence needed before another useful attempt

   Shell mode can also use `evidence record SYMBOL` with --hypothesis,
   --prediction, --observation and --unlock. These notes grant no match credit
   and do not authorize another attempt.

For donor work, verify the source license and content/revision first. Use the
existing sourcealign compiler/discovery/import path. Inspect `evidence donors`;
legacy objects are not content-pinned compiled evidence. Try new/expanded target
relatives, not an unchanged exhausted corpus. Object similarity is not acceptance.

Before claiming completion, run the gates your role permits. An integrator must
verify lint, the configured build and all 16 hashes. A restricted matcher reports
only its tool's acceptance state; it must not claim a linked result that the
verifier has not produced. Report verified native functions/bytes separately
from saved partials, fuzzy/data/assembly credit, queued proposals and blockers.
Use `evidence yield` for conservative measured attribution; missing cost is not
zero cost and differing assignments do not establish a model leaderboard.

Execute bounded useful work now. Do not stop at a plan or continue an unchanged
experiment simply to consume the remaining budget.
